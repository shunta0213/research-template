書式:


## 2026-10-04 データのスナップショットを DVC で Google Drive に保存する

- 背景: `data/` は git 管理外で，計算機の故障や移行で失われうる。論文の図の元データを後から取り出せるようにしたい
- 決定: `scripts/archive_data.sh` で `data/` のサブディレクトリごとの `tar.zst` を `archive/data-<日付>/` に作り，
  それを `dvc add` して Google Drive（共有ドライブ）に `dvc push` する。接続は Google Drive API（サービスアカウント）
- 却下した案:
  - `data/` を直接 DVC で追跡する（`data/runs/` の小さなファイルが大量にあり，Google Drive の API の
    ファイル単位のレート制限で push/pull が非常に遅い）
  - DVC 標準のブラウザ認証（DVC 共用の OAuth アプリは Google にブロックされることがあり，
    ブラウザの無いクラスタからは使えない）
- 鍵の置き場所: サービスアカウントの鍵はプロジェクト内の `.secrets/`（git 管理外）に置き，`.dvc/config.local` から
  相対パスで参照する。`~/.config/...` のようなホームディレクトリの共通の場所に置くと，プロジェクト間で
  鍵が共有され，どのプロジェクトがどの鍵を使っているか分かりにくくなるため
- 影響: 各プロジェクトで `scripts/setup_dvc.sh` によりフォルダ ID と鍵を設定する必要がある

## 2026-10-04 クラスタでの実行は「複数のコマンドをまとめたタスク」を cjob sweep で投入する

- 背景: パラメータスイープを研究室のクラスタ（cjob）でも手元（pueue）と同じ add-tasks スクリプトから投入したい。
  1 コマンドは数秒〜数十分のことが多く，1 コマンドごとに cjob のタスクを立てるとコンテナ起動などの
  オーバーヘッドの方が大きくなる
- 決定: `commands_per_task` 個のコマンドを 1 タスクにまとめて `data/tasks/*.json` に書き出し，
  `cjob sweep` の `_INDEX_` 番目のタスクを `python -m src.task_runner` が `workers` 並列で実行する
  （タスク内の小さな pueue）。重いパラメータ点が偏らないよう，コマンドはタスクに飛び飛びに配る。
  `commands_per_task` と `time_limit` は実験ごとに人が決める。投入先は add-tasks の `BACKEND` で切り替える
- 却下した案:
  - パラメータ点ごとに `cjob add`（投入 500 件の上限にすぐ当たる）
  - 1 コマンド = sweep の 1 タスク（短いコマンドではオーバーヘッドが支配的）
  - コマンドごとの所要時間の見積もり関数から詰め合わせ・`time_limit` を自動計算する
    （実験ごとに見積もり関数を書くのは現実的でない）
- 影響: 実験スクリプトは変更不要。add-tasks ごとに `CJOB` の値を決める必要がある

## 2026-10-04 run ディレクトリを結果に影響するパラメータの hash で決める

- 背景: スイープを中断・追加したときに，どのパラメータ点が計算済みかを簡単に判定したい
- 決定: `data/runs/<実験名>/<hash>/` とし，`<hash>` は `RunStore.param_types` のパラメータだけから計算する。
  `output.npz` の有無で完了を判定する
- 却下した案: パラメータ値をディレクトリ名に並べる（パラメータが増えると長くなり，配列パラメータを扱えない）
- 影響: ハッシュ対象のパラメータを増やすと既存データと対応しなくなるため，その場合は実験名を `-v2` にする
