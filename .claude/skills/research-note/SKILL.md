# 研究ノートを作る

`notes/TEMPLATE.md` の形式で `notes/YYYY-MM-DD.md`（今日の日付）を作る。既にあれば追記する。
ルールは `notes/README.md` と `docs/development.md`「記録を残す」。

## 1. 材料を集める（読むだけ）

前回のノート（`notes/` の日付が最新のファイル）の日付以降について:

- `git log --since=<前回の日付> --oneline` と，変更されたファイル
- 新しいラン: `data/runs/<name>/` ごとに，前回以降に `output.npz` ができた run の数
  （`find data/runs -name output.npz -newer notes/<前回>.md` など）。中身の数値は読まなくてよい
- 新しい図: `analysis/**/figs/` で前回以降に更新されたファイル
- `docs/decisions.md` に前回以降に追記された項目

`data/` が大きいときは件数を数えるだけにし，ファイルを開いて数値を集計しない。

## 2. 下書きする

- **やったこと**: 集めた事実（実験名・パラメータ範囲・ランの件数・コミット）を箇条書きにする
- **結果**: 図のパス（`analysis/<name>/figs/...`）と，注目する run があればその hash へのリンクを書く。
  **数値や傾向を推測で書かない**（図を見ていないのに「〜が減少した」などと書かない）
- **次にやること**: コミットや TODO から分かるものだけ

## 3. ユーザーに聞く

次はユーザーにしか書けないので，下書きを見せて聞く（空欄のまま埋めない）:

- 目的（今日確かめたかったこと）
- 考察（結果から言えること・言えないこと，予想と違った点）
- うまくいかなかったこと・やめたこと

## 4. 書く

- 答えをもとに `notes/YYYY-MM-DD.md` を書く。既存のノートに追記するときは，元の記述を消さない
- 方式・パラメータの決定が含まれていたら，`docs/decisions.md` にも追記するか聞く
